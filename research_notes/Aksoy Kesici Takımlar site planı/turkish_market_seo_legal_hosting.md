## 1. Competitors: which Turkish websites appear for "kesici takım", "karbür uç", "Korloy bayi", "Iscar uç fiyat", "torna kateri", "kanal kateri", "CNC takım", "karbür matkap", "parmak freze", "kılavuz"? What do they do well or poorly?

### Takeaway
The niche splits into three groups:
- **Online shops with exact-code product pages and visible prices.** These hold the "fiyat" and code queries: akiteknik.com, ekesici.com, cnrtakim.com, takimsanayi.com, teknikdukkan.com, cnctakim.com.
- **General marketplaces and price-comparison sites** for generic queries: n11.com, cimri.com.
- **Regional authorized dealers/distributors with dated brochure sites**: guneykesici.com, temak.com.tr, egtkesici.com, proarttech.com, alpperteknik.com, gaprex.com.tr.

A fast, mobile-first, code-searchable catalog with a frictionless WhatsApp quote is a realistic gap. Price-intent ("fiyat") queries will stay hard to win without showing prices.

### Inferences
- **What competitors do well**
  - Exact ISO-code product pages with the code at the start of the title and slug (akiteknik, cnrtakim, takimsanayi).
  - Listing both code variants in one title, e.g. "APMT 1604 … (APKT 1604)".
  - Dimension-rich titles for solid tools (ekesici).
  - A few educational posts (celikkesicitakimlar code guide, atateknik and kutayteknik explainers).
- **Observable weaknesses**
  - Many authorized dealers (Temak, Güney Kesici, EGT, Kesici Takım Evi) run legacy sites, indexed over http://, with `.html`/`.htm` pages and PDF-style e-catalogs instead of indexable per-product pages.
  - Some shops use query-string or numeric-ID URLs (takim-market, karburuc, cnctakim) or Wix product URLs (frezetek).
  - Price display is inconsistent across EUR, USD and TL, with or without KDV.
- **Opportunity for Aksoy.** Combine an authorized-dealer style trust signal (field sales, technical advice) with modern e-commerce SEO: per-code pages, brand pages, calculators and guides. The sites that rank on codes are shops with prices, so Aksoy should target **code + "teklif"/"stok"/"muadil"** and informational queries rather than expect to win "fiyat" queries without prices.
- Marketplaces (n11, cimri) will keep the broad "torna kateri fiyatları" type queries. A small static site has better odds on long-tail code queries and on "bayi + city/region" queries.

### Gaps
- The true google.com.tr rank order, search volumes and click-through could not be measured. Run the queries from a Turkish IP or use Google Search Console, Ahrefs or Semrush with the TR database.
- Not measured: speed (Core Web Vitals), mobile rendering and WhatsApp-button usage on competitor sites. Fetching was blocked. Run PageSpeed Insights on akiteknik.com, ekesici.com, cnrtakim.com, guneykesici.com and temak.com.tr before launch.
- Not found: a Turkish site for Iscar itself, the Kyocera Turkey distributor, or the SANT distributor. The search budget ran out.

## 2. Keyword research: high-intent Turkish terms, ISO-code long tail, search behavior, URL slugs, title/meta patterns

### Takeaway
Turkish machinists search by **ISO insert code + geometry/chipbreaker + grade**, often with the colloquial word **"elmas uç"**, even for carbide. The vocabulary to cover:

| Product type | Search terms |
|---|---|
| Inserts | "elmas uç", "karbür uç", "sert metal uç", "sert maden uç", "kesici uç", "insert" |
| Solid tools | "karbür freze", "elmas freze", "parmak freze", "küre parmak freze", "karbür matkap" |
| Holders | "torna kateri", "dış çap torna kateri", "kanal kateri", "kanal açma kateri", "kesme kateri" |

Use ASCII-transliterated slugs and code-first titles.

### Inferences
- **Recommended slug scheme** (ASCII, lowercase, hyphenated; ç→c, ğ→g, ı→i, İ→i, ö→o, ş→s, ü→u):
  - `/katalog/` → `/katalog/tornalama/` → `/katalog/tornalama/torna-elmas-uclari/` → `/katalog/tornalama/torna-elmas-uclari/cnmg/`
  - Product: `/urun/iscar-cnmg-120408-pp-ic907/` (brand + full ISO code + chipbreaker + grade, all in the slug)
  - Brand: `/marka/iscar/`, `/marka/korloy/`, `/marka/tungaloy/`, `/marka/guhring/`, `/marka/kyocera/`, `/marka/deskar/`, `/marka/sant/`
  - Calculators: `/hesaplama/kesme-hizi-devir/`, `/hesaplama/ilerleme-hesabi/`, `/hesaplama/kilavuz-matkap-capi/`, `/hesaplama/talas-kaldirma-miktari/`
  - Blog: `/blog/torna-elmas-uc-kodlari-nasil-okunur/`, `/blog/cnmg-dnmg-wnmg-farki/`, `/blog/apmt-apkt-farki/`
  - Contact: `/iletisim/`, `/teklif-sepeti/`. Optional local pages if the service area is real: `/bolge/istanbul/`, `/bolge/kocaeli/` etc.
- **Product title pattern** (≈60 chars): `{ISO kod}-{talaş kırıcı} {kalite} {Marka} {Tür} | Aksoy Kesici`. Example: `CNMG 120408-PP IC907 Iscar Torna Elmas Uç | Aksoy Kesici`.
  - Where a code has an alternate form (APMT/APKT, CNMG 120408 / CNMG 432), mention it in the H1 subtitle or spec table rather than stuffing the title.
- **Meta description pattern**: `{Marka} {kod} karbür (elmas) uç: {geometri}, {köşe radyüsü}, {malzeme grubu P/M/K}. Stok ve fiyat için WhatsApp'tan hızlı teklif alın — {bölge} sahada teslim.`
- **Solid-tool titles should include dimensions**, as eKesici does: `Ø6 x 45 x 100 Z4 TiSiN Karbür Parmak Freze – {Marka}`.
- **High-intent modifiers to add** in H1/H2/FAQ copy: "teklif", "stok", "bayi", "muadil" (equivalent), "fiyat teklifi", "toptan", "kutu (10'lu paket)", plus city/region names for field-sales areas.
- **"Muadil" (equivalent/cross-reference) pages** could be a differentiator, e.g. "CNMG 120408 muadilleri: Iscar / Korloy / Tungaloy / Kyocera". Machinists search by code regardless of brand. (Inference; volume not verified.)
- Put the ISO code in the **first words** of title, H1 and slug. Include the code with and without the space (`CNMG120408`, `CNMG 120408`) in body or spec text, since competitor titles use both forms.

## 3. Local / B2B SEO for a business without a storefront: Google Business Profile, schema.org, product rich results without price

### Takeaway
- **Google Business Profile:** set Aksoy up as a **service-area business** with the address hidden and up to 20 service areas within ≈2 hours' drive.
- **Rich results without prices:**
  - Google **merchant listings require a price > 0**.
  - **Product snippets need at least one of offers, review or aggregateRating.**
  - A catalog with no prices and no genuine reviews will therefore normally **not get product rich results**.
- Still use Product markup for entity understanding, and get visibility from Organization/LocalBusiness, BreadcrumbList and Article markup.

### Cited Findings
- **GBP for service-area businesses (SAB).** A business that serves customers at their location should hide its address and set a service area. Showing a non-customer-facing address is a common suspension cause. Up to 20 service areas are allowed, and the overall area should not extend beyond about 2 hours' drive from the base — [Google Business Profile guidelines](https://support.google.com/business/answer/3038177?hl=en); [Manage your business address](https://support.google.com/business/answer/2853879?hl=en); [Local Falcon SAB guide](https://www.localfalcon.com/blog/how-to-set-up-google-business-profile-for-servicearea-businesses)
- **Product snippets require one of `review`, `aggregateRating` or `offers`**, plus `name`. `offers` is needed for price display, and within `offers`, `price` and `priceCurrency` are required — [Google product snippet docs](https://developers.google.com/search/docs/appearance/structured-data/product-snippet); [Shopify community on the "Either offers, review or aggregateRating" error](https://community.shopify.com/t/i-dont-know-how-to-fix-this-either-offers-review-or-aggregaterating-should-be-specified/205899)
- **Merchant listing experiences require `offers.price` > 0** plus `priceCurrency`. A price of 0 is only allowed for special cases such as contract phones or subscriptions — [Google merchant listing docs](https://developers.google.com/search/docs/appearance/structured-data/merchant-listing); [Merchant Center product data spec](https://support.google.com/merchants/answer/7052112?hl=en); [technicalseo.com comparison](https://technicalseo.com/insights/blog/product-schema-google-merchant-vs-google-search/)
- **Review snippets need `ratingValue` and `reviewCount` for AggregateRating** — [Google review snippet docs](https://developers.google.com/search/docs/appearance/structured-data/review-snippet)

### Inferences
- **Do not** add a fake `price: 0` or invented reviews to get rich results. Google says 0 is not valid for merchant listings, and fabricated reviews breach its guidelines (inference from the docs above).
- Use `Product` with `name`, `sku`/`mpn` (ISO code + grade), `brand` (`Brand`), `image`, `description`, `category` and `additionalProperty` (`PropertyValue` for IC, s, rε, chipbreaker, grade, ISO P/M/K/N/S/H). This helps Google understand the product even without rich-result eligibility.
- If an `Offer` is ever added without a public price, background knowledge suggests it will fail the product-snippet price requirement. Leaving `offers` out is cleaner. A future option is to show "fiyat: teklif ile" on the page only, not in schema. (Inference; Rich Results Test behavior not verified this session.)
- **Site-wide schema** (background knowledge, verify with schema.org and the Rich Results Test):
  - `Organization` (name "Aksoy Kesici Takımlar", logo, `telephone` "+90-535-610-19-89", `sameAs` to GBP/social, `contactPoint` with `contactType` "sales" and `availableLanguage` "tr").
  - `LocalBusiness` (or `Store`/`WholesaleStore`) with **no public `address` street** (or only `addressLocality`/`addressRegion`, consistent with the hidden-address GBP), `areaServed` as a list of `City`/`AdministrativeArea` entries that match the GBP service areas, and `openingHoursSpecification`.
  - `BreadcrumbList` on every catalog/product page, `Article`/`BlogPosting` on blog posts, and `WebSite`.
- **FAQPage markup**: background knowledge (not re-verified this session) says Google restricted FAQ rich results in 2023 to authoritative government and health sites. FAQ markup will likely not produce a visible rich result, but FAQ content still helps long-tail queries. **Verify in Google's FAQ docs.**
- hreflang is not needed for a Turkish-only site. Set `<html lang="tr">` and `og:locale` `tr_TR`.
- Provide an XML sitemap (split product URLs if over 50k; unlikely) and submit it to Google Search Console. Bing Webmaster Tools and Yandex Webmaster are optional extras (Yandex has some Turkish usage; not verified this session).

## 4. Turkish legal requirements for a catalog site with no online payment: KVKK, cookies, 6563 & ETBİS, provider info, trademarks

### Takeaway
- **ETBİS:** registration is **not required** if the site does not let users conclude a contract or place an order online. ⚖️ Confirm that a WhatsApp "quote basket" is not an online order.
- **KVKK (6698) applies** whenever personal data is processed (WhatsApp messages, forms, server logs). Publish an **aydınlatma metni**. Rely on legal bases other than consent where possible. Note that the 2024 amendment (Law 7499) **removed explicit consent as the general basis for cross-border transfers**, which matters for WhatsApp/Meta and foreign hosting.
- **Cookies:** a banner with equal Accept and Reject is required **only if** non-essential cookies (e.g. GA4, ads) are used. Truly cookieless analytics generally avoids it.
- **Brands:** reselling genuine goods is covered by exhaustion (SMK m.152), and descriptive use is allowed (SMK m.7/5). Do **not** claim "yetkili bayi" unless authorized, and get permission before using brand logos. ⚖️

### Cited Findings
**ETBİS / 6563 sayılı Elektronik Ticaretin Düzenlenmesi Hakkında Kanun**
- Providers whose site lets users conclude contracts or place orders for goods or services must register in ETBİS before starting. A site that does not enable online contracts or orders has no ETBİS registration or notification duty. Companies that only sell offline are outside the duty — [T.C. Ticaret Bakanlığı – Elektronik Ticaret SSS](https://ticaret.gov.tr/ic-ticaret/sikca-sorulan-sorular/elektronik-ticaret); [Ataylar Avukatlık](https://ataylaravukatlik.av.tr/e-ticaret-sitem-icin-etbis-sistemine-kayit-zorunlulugum-var-midir/); [Karadağ Avukatlık (2026)](https://www.karadagavukatlik.av.tr/e-ticaret-siteleri-icin-etbis-sistemine-kayit-zorunlulugu/)
- **6563 m.3 ("Bilgi verme yükümlülüğü")**: before a contract is concluded through electronic communication, the service provider must give easily accessible, current identifying information and the technical steps to conclude the contract. It must also let the buyer store the contract terms — [6563 konsolide metin (Lexpera)](https://www.lexpera.com.tr/mevzuat/kanunlar/elektronik-ticaretin-duzenlenmesi-hakkinda-kanun-6563/1); [Kanun PDF (Adalet Bakanlığı)](https://mgm.adalet.gov.tr/Resimler/SayfaDokuman/211020191144436563.pdf)
- **Provider info the merchant (tacir) should show** under an "iletişim" heading: ticaret unvanı, MERSİS numarası, merkez adresi, KEP adresi, e-posta and telefon. This was reported in search summaries of commentary on 6563 and its regulation — [Erdem Varol – 6563](https://www.erdemvarol.com.tr/6563-sayili-kanun/); [Verimor – 6563](https://www.verimor.com.tr/makaleler/6563-sayili-elektronik-ticaretin-duzenlenmesi-hakkindaki-kanun)

**TTK m.1524 (company website obligation)**
- The obligation to open a website and publish mandatory announcements within 3 months of registration applies only to **capital companies subject to independent audit** (bağımsız denetime tabi). Sole proprietorships are not covered — [MTHS – TTK 1524](https://mths.net.tr/ttk-1524/); [Verda Hukuk](https://www.verdahukuk.com/tr-TR/bagimsiz-denetime-tabi-ve-internet-sitesi-acmasi-zorunlu-olan-sirketler/14/72); [Adalet Dergisi article](https://dergipark.org.tr/tr/pub/adaletdergisi/article/1799385)

**KVKK – Çerez Uygulamaları Hakkında Rehber**
- Cookie categories: strictly necessary (zorunlu), functional, performance/analytics and advertising/marketing. Strictly necessary cookies (session integrity, authentication, security) generally do not need explicit consent — [Esenyel Partners roadmap](https://www.esenyelpartners.com/tr/kvkk-cerez-rehberi-uyarinca-web-siteleri-icin-uyum-yol-haritasi/); [bthaber](https://www.bthaber.com/kvkkin-cerez-rehberi-veri-sorumlulari-icin-pratik-tavsiyeler-iceriyor/)
- Standard Google Analytics and similar third-party analytics are **not** "strictly necessary" under the Guide and need explicit consent (açık rıza). Consent must be specific, informed and given by an active affirmative act; simply entering the site is not consent — [Esenyel Partners](https://www.esenyelpartners.com/tr/kvkk-cerez-rehberi-uyarinca-web-siteleri-icin-uyum-yol-haritasi/); [Moral Hukuk](https://www.moral.av.tr/tr/hukuki-haberler/cerez-uygulamalari-hakkinda-rehber-yayinlandi-729)
- Banners should offer "Tümünü Kabul Et", "Tümünü Reddet" and "Tercihleri Yönet" with equal prominence — [Dijilegal 2026 guide](https://dijilegal.com/blog/cerez-politikasi-kvkk-rehberi)
- A search result mentions an **updated** KVKK cookie guide ("güncellenen Çerez Uygulamaları Hakkında Rehber yayımlandı") — [SRP-Legal](https://www.srp-legal.com/tr/kisisel-verileri-koruma-kurumu-tarafindan-guncellenen-cerez-uygulamalari-hakkinda-rehber-yayimlandi/); original announcement — [AA](https://www.aa.com.tr/tr/bilim-teknoloji/kisisel-verileri-koruma-kurumu-cerez-uygulamalari-hakkinda-rehber-hazirladi-/2617954)
- With cookieless analytics that process no personal data (Plausible, Cloudflare Web Analytics), a cookie banner may not be necessary. This is the view of secondary commentary — [Dijilegal](https://dijilegal.com/blog/cerez-politikasi-kvkk-rehberi); [Cookienox – Cloudflare & KVKK 2026](https://cookienox.com/blog/cloudflare-turkiye-gizlilik/); [Dalnet – Plausible](https://www.dalnet.tr/guncel-icerikler/plausible-analytics-nedir/)

**KVKK 2024 amendment (Law 7499) – cross-border transfer (yurt dışına aktarım)**
- Explicit consent stopped being a general basis for transfers abroad. Consent-based transfers were accepted only until **1 September 2024**. The new order is adequacy decision → appropriate safeguards (incl. standard contracts / BCRs) → incidental (arızi) cases — [KVKK Reformu 2024 (M.B. Kaya)](https://mbkaya.com/hukuk/kvkk-reformu.pdf); [Güleryüz](https://www.guleryuz.av.tr/tr/news-publications/detail/https-wwwguleryuzavtr-tr-news-publications-detail-6698-sayili-kisisel-verilerin-korunmasi-kanunu-nda-degisiklikler); [Güneş Partners 2026](https://www.gunespartners.com/makale/yurt-disina-veri-aktarimi-7499-sayili-kanun); [KVKK Yurt Dışına Aktarım Rehberi](https://www.kvkk.gov.tr/Icerik/8142/Kisisel-Verilerin-Yurt-Disina-Aktarilmasi-Rehberi)
- Standard contracts must be **notified to the KVKK Authority within 5 business days** of signature. Failure to notify carries fines reported at **50,000–1,000,000 TL** — [Cottgroup](https://www.cottgroup.com/tr/blog/kvkk-gdpr/item/standart-sozlesme-bildirim-yukumlulugu-ve-yaptirimlari); [Birasyo](https://birasyo.com/tr/blog/kvkk-yurt-disi-veri-aktarimi-yeni-yonetmelik-standart-sozlesme/)
- A search summary of these sources said that customer data processed via WhatsApp Business goes to US/Ireland servers and should use the standard-contract mechanism. The exact originating page among the results could not be confirmed — [Netta](https://nettacompany.com/blog/kvkk-yurt-disina-veri-aktarimi-sunucunuz-yurt-disindaysa); [Güneş Partners](https://www.gunespartners.com/makale/yurt-disina-veri-aktarimi-7499-sayili-kanun)

**Trademarks – 6769 sayılı Sınai Mülkiyet Kanunu (SMK)**
- **Exhaustion (tükenme), SMK m.152/1.** Acts concerning products put on the market (Turkey adopted *international* exhaustion) by the right holder or with its consent fall outside the right. This requires (a) placement on the market by or with consent of the owner and (b) genuine, original goods — [DergiPark – tükenme istisnaları](https://dergipark.org.tr/tr/download/article-file/5514351); [Rumeli Hukuk](https://www.rumelihukuk.com/marka-hakkinin-tukenmesi/)
- **Fair use, SMK m.7/5.** The owner cannot prevent honest commercial use that indicates kind, quality, intended purpose and similar characteristics of goods, including spare parts and accessories where needed to show intended use. The use must be "dürüst" and consistent with commercial practice — [Av. Zeki Emre Kurt – SMK 7/5](https://www.emrekurt.av.tr/blogs/2025/07/21/marka-haklari-nerede-biter-smk-m-7-5-marka-hakkinin-sinirlari/); [Fırat Gültekin – internette dürüst kullanım](https://firatgultekin.com.tr/markanin-internette-durust-kullanimi/); [SMK m.7 text](http://www.sinaimulkiyetkanunu.com/sinai-mulkiyet-kanunu-madde-7/)
- **Internet-specific prohibition.** Using a mark without right or legitimate connection as a domain name, redirect code, keyword or similar with commercial effect is prohibited. A search summary of Hukuki Haber cited this as "SMK Article 4". Background knowledge suggests it is **SMK m.7/3(f)**; verify — [Hukuki Haber](https://www.hukukihaber.net/6769-sk-kapsaminda-internet-ortaminda-islenen-marka-suclari); [Kurtuluş & Partners](https://kurtuluspartners.com/internette-marka-hakkinin-ihlali%CC%87/)

### Inferences
- **ETBİS ⚖️.** The quote basket only composes a WhatsApp message. No contract is concluded on the site, and there is no payment, order confirmation or "sipariş ver" button. This supports "no ETBİS duty". Wording matters: use "Teklif Sepeti" / "Teklif İste", never "Sepete Ekle → Sipariş Ver". If online ordering is added later, register in ETBİS before launch.
- **Provider info (strong practice even without e-commerce).** Add a footer and an "Künye / Yasal Bilgiler" page with:
  - ticaret unvanı (legal entity name; for a şahıs işletmesi, the owner's name + business name)
  - MERSİS no (if a company) or vergi dairesi / vergi no
  - adres (at least registered address; the GBP address can stay hidden publicly)
  - telefon, e-posta, KEP (if any)
  - Ticaret Sicil no / oda kaydı (chamber)

  A static catalog arguably is not concluding contracts. However, Turkish commercial-communication and commercial-paper rules also push merchants to show these details ⚖️.
- **KVKK aydınlatma metni** (6698 m.10) should name the veri sorumlusu, purposes (teklif hazırlama, iletişim), legal basis (likely m.5/2-c "sözleşmenin kurulması" and m.5/2-f "meşru menfaat" rather than açık rıza), recipients (Meta/WhatsApp, hosting provider), transfer abroad, collection method and m.11 rights.
  - Link it next to the WhatsApp button / basket ("WhatsApp'a yönlendirileceksiniz; Aydınlatma Metni").
  - A pre-ticked or mandatory "açık rıza" checkbox is **not** recommended. It is unnecessary where another legal basis applies and can be invalid if bundled. ⚖️
- **Transfer abroad ⚖️.** Static hosting abroad (Cloudflare/Vercel/Netlify, US) and WhatsApp (Meta) both involve processing outside Turkey. With no form and no analytics cookies, the site itself processes little beyond server logs. Still, take legal advice on whether Meta's or the host's terms provide a valid "uygun güvence" and whether a standard-contract notification is needed.
- **Cookie banner.**
  - No banner is needed if the site sets **no non-essential cookies or local storage identifiers**: cookieless analytics (Cloudflare Web Analytics; see §8), no embedded YouTube/Maps that set cookies, and `localStorage` used only for the quote basket.
  - Basket storage is user-requested functionality, i.e. strictly necessary or functional. Disclose it in a short Çerez/Gizlilik Politikası.
  - If GA4, Meta Pixel or YouTube embeds are added, a compliant banner is required. ⚖️
- **VERBİS.** Small businesses below the KVKK Board's thresholds are usually exempt from VERBİS registration. Thresholds change, so verify current figures. ⚖️ (Not researched this session; see Gaps.)
- **Safe brand wording.**
  - Use the plain-text brand names in a descriptive way: "Iscar, Korloy, Tungaloy, Gühring, Kyocera, Deskar ve SANT ürünlerinin tedariki", "Orijinal ürün, fatura ile", "{Marka} uyumlu / {Marka} kodu".
  - Avoid "Yetkili Bayi", "Resmi Distribütör" and "Türkiye Bayisi" unless there is a written dealership agreement for that brand. Misleading authorization claims also risk unfair-competition claims (TTK m.55) ⚖️.
  - **Logos:** prefer plain text or a neutral "Markalar" list. Use official logos only with permission or as allowed by a dealer agreement. Logos are also protected as artistic works.
  - Add a disclaimer: "Tüm marka adları ve logolar ilgili sahiplerine aittir; yalnızca ürünleri tanımlamak amacıyla kullanılmıştır. Aksoy Kesici Takımlar, aksi belirtilmedikçe bu markaların yetkili temsilcisi değildir."
  - Do not use competitor or brand names in the **domain name**.
  - Brand-name SEO keywords on pages that genuinely sell that brand's original goods fall within descriptive use under m.7/5 plus exhaustion ⚖️.
  - Grey-market imports are a risk area for exhaustion. Turkey's international exhaustion helps, but genuine goods are a precondition.

## 5. WhatsApp integration best practices

### Takeaway
Use `https://wa.me/905356101989?text=<encodeURIComponent(message)>`: number in international format with no +, zeros, spaces or dashes, and the message UTF-8 percent-encoded (Turkish characters and newlines `%0A` included). ### Cited Findings
- **Format.** `https://wa.me/<number>` uses the full international number without zeros, brackets or dashes. Pre-filled text is `https://wa.me/<number>?text=<urlencodedtext>` — [BusinessChat help](https://help.businesschat.io/en/articles/6517838-how-to-build-a-whatsapp-click-to-chat-url-wa-me); [WATI](https://support.wati.io/en/articles/11462980-how-to-create-whatsapp-click-to-chat-links)

Unencoded special characters break the link on some devices — [BusinessChat](https://help.businesschat.io/en/articles/6517838-how-to-build-a-whatsapp-click-to-chat-url-wa-me); [u2l.ai guide](https://u2l.ai/blog/whatsapp-click-to-chat-link); [wha.tools](https://wha.tools/blog/how-to-create-click-to-whatsapp-link-wa-me)
- **Non-ASCII characters** must be UTF-8 encoded then percent-encoded (e.g. ü → `%C3%BC`) — [Google URL structure](https://developers.google.com/search/docs/crawling-indexing/url-structure); [MERJ on URL encoding](https://merj.com/blog/url-encoding-done-right-best-practices-for-web-developers-and-seos)
- **WhatsApp Business app catalog.** Up to **500 items**. Each item can have up to 10 photos, name (required), price, description, product code and a website link. Items and the full catalog can be shared in chat. There is **no checkout** and no inventory sync — [InstantReply 2026 guide](https://www.instantreply.co/blog/whatsapp-catalog-guide-2026); [respond.io](https://respond.io/blog/whatsapp-business-app); [WhatsApp Business resources](https://whatsappbusiness.com/resources/resource-library/whatsapp-business-app-resources-whatsapp-business-catalog/)

## 6. Hosting: Vercel vs Netlify vs Cloudflare Pages vs GitHub Pages (free tiers 2026), performance and blocking in Turkey, domains

### Takeaway
- **Recommendation: Cloudflare Pages (or Cloudflare Workers static assets) with a custom domain from day one.**
  - Unlimited bandwidth and commercial-friendly free tier.
  - Cloudflare has Istanbul and Izmir PoPs.
  - Cloudflare Web Analytics is free.
- **Why not the others:**
  - **Vercel Hobby forbids commercial use**, so a dealer site needs Pro.
  - **GitHub Pages excludes online business sites** whose main purpose is commercial transactions.
  - **Netlify Free** was cut to ~15 GB/month equivalent in April 2026 and hard-pauses the site when exceeded.
- **Critical Turkey issue:** the default subdomains **\*.pages.dev, \*.vercel.app and \*.netlify.app have each been access-blocked in Turkey**. pages.dev was reported blocked again on 25 Aug 2026. **"Free subdomain first, custom domain later" will not work for Turkish visitors.** Buy the domain now (.com.tr ≈ 50–100 TL/yr promo; .com ≈ 560 TL/yr).

### Cited Findings
**Vercel**
- The Hobby plan is for **non-commercial, personal use only**. Commercial usage includes any deployment "used for the purpose of financial gain of anyone involved", including advertising the sale of a product or service. Hobby includes 100 GB transfer and 1M function invocations per month. Over the limit, a feature is paused until 30 days have passed — [Vercel Hobby plan docs](https://vercel.com/docs/plans/hobby); [Vercel community discussion #1411](https://github.com/vercel/community/discussions/1411); [justinmckelvey.com 2026](https://justinmckelvey.com/blog/is-vercel-free)
- Vercel has 19 compute regions and a CDN with 126 PoPs in 94 cities across 51 countries. No Istanbul compute region ("ist1") was found — [Vercel regions](https://vercel.com/docs/regions); [Vercel CDN overview](https://vercel.com/docs/cdn)
- **vercel.app blocking in Turkey.** Blocked by USOM on **6 Dec 2023** (phishing), then by BTK decision dated **27 Mar 2024** (no. 490.05.01.2024.-207622). Users reported custom domains or VPN as workarounds — [İFÖD EngelliWeb – Vercel](https://ifade.org.tr/engelliweb/vercel-erisime-engellendi/); [EngelliWeb on X](https://x.com/engelliweb/status/1733368377186701677); [Vercel community #5862 ERR_TIMED_OUT](https://github.com/vercel/community/discussions/5862)

**Netlify**
- The Free plan is credit-based: **300 credits/month**. Since **17 Apr 2026**, bandwidth costs **20 credits/GB** (was 10), so ≈15 GB/month if nothing else is used. A production deploy costs **15 credits**, compute 10 credits/GB-hour and web requests 2 credits per 10k. The free cap is **hard: sites pause until the next cycle** — [Netli.fyi 2026](https://netli.fyi/blog/netlify-free-plan-limits-2026); [Temps.sh](https://temps.sh/compare/vs-netlify); [AgentDeals](https://agentdeals.dev/vendor/netlify)

**Cloudflare Pages**
- Free plan: unlimited sites, **unlimited bandwidth**, **500 builds/month**, **20,000 files per deployment**, 1 concurrent build, 20-min max build — [DEV Community 2026](https://dev.to/david_viejo_4d48fdfa7cfff/cloudflare-pages-free-tier-limits-pricing-2026-1f8f); [Temps.sh](https://temps.sh/blog/cloudflare-pages-free-tier-limits-2026); [Nayan Kyada](https://nayankyada.com/blog/cloudflare-pages-pricing-2026-free-tier-limits-workers-costs-when-to-upgrade)

### Inferences
- **Pick Cloudflare Pages** (or Workers + static assets) for these reasons:
  - Commercial use on the free plan is not prohibited in the sources found (verify the ToS).
  - Unlimited bandwidth suits a heavy 3D homepage and image catalog.
  - 500 builds/month is plenty even if a Google Sheet triggers a rebuild on each publish.
  - Free SSL and DNS, and Turkish PoPs.
  - Native Web Analytics (cookieless).
  - Redirect rules (e.g. a `/wa` click redirect) and a Bulk Redirect from `*.pages.dev` to the custom domain.
- **Vercel Hobby is non-compliant for this business** because it advertises products for sale. Vercel would mean Pro (paid). Netlify Free's ~15 GB and hard pause are risky with 3D assets. GitHub Pages' ToS excludes sites "primarily directed at facilitating commercial transactions". A no-payment catalog is a grey zone, but Cloudflare avoids the question.
- **Launch with the custom domain** because the platform subdomains are blocked in Turkey. Recommended: **aksoykesici.com.tr** or **aksoykesicitakimlar.com.tr** (check availability).
  - .com.tr is cheap via a Turkish registrar.
  - .com.tr is **not** sold by Cloudflare Registrar (background knowledge; verify). Register .com.tr at a Turkish registrar and point nameservers to Cloudflare (free plan) or add CNAMEs.
  - Optionally also buy the .com and 301 it to the .com.tr.
- Turkish ISPs block by DNS/SNI on the platform hostname. A custom domain on shared Cloudflare IPs has worked during past pages.dev blocks. However, broader IP-level blocking of Cloudflare ranges has occasionally hit unrelated sites in Turkey. Keep the static build portable (plain HTML output) so it can move to a Turkish host (e.g. a cheap cPanel/LiteSpeed host in Istanbul) within an hour if needed.
- **Performance from Turkey:**
  - With a static site, CDN location matters less than page weight. Keep the 3D homepage progressive: a poster image first, then lazy-load the WebGL/three.js model after interaction or idle, with Draco/meshopt-compressed GLB under ~2–3 MB.
  - **No head-to-head latency benchmark from Turkey** (Cloudflare vs Vercel) was found. Cloudflare's Istanbul/Izmir presence makes it the likely faster option, but the community reports show routing can go to AMS/DUS on the free plan. Test with real Turkish mobile networks (Turkcell, Vodafone TR, Türk Telekom).
- **Image optimization.** Cloudflare Images/Polish are paid features (background knowledge; verify). For a free setup, pre-optimize images at build time (e.g. Astro `<Image>` / sharp → AVIF/WebP with `srcset`).

## 7. Future content management for a non-technical owner (phone-first)

### Takeaway
For a Turkish small-business owner editing from a phone, **Google Sheets → JSON at build time** (Sheets app + a "Yayınla" deploy hook) is the simplest and cheapest way to manage hundreds of product codes. Add **TinaCMS** (best visual editing, free for 2 users) or **Decap CMS** (free, Git-based, dated UI) only for blog posts. **Sanity** (free 3 users / 10k documents) is the most powerful but the most developer-dependent.

### Cited Findings
- **Decap CMS** is free with no paid tiers or seat limits. Its UI is described as dated; non-technical editors struggle; mobile editing works but is "cumbersome" — [Lucky Media – Decap review 2026](https://www.luckymedia.dev/insights/decap-cms); [UnfoldCMS – Decap vs Tina](https://unfoldcms.com/blog/decap-vs-tinacms-git-cms)
- **TinaCMS**:
  - Free tier up to 2 users, with visual editing and Tina Cloud Git integration.
  - The admin UI is "reasonably intuitive"; non-technical editors can do basic edits and image uploads "within an hour".
  - Supports various screen sizes, including iOS and Android.
  - Recommended for weekly editing with non-technical collaborators.
  - Sources: [Lucky Media – Tina review 2026](https://www.luckymedia.dev/insights/tina-cms); [MakerStack – TinaCMS 2026](https://makerstack.co/reviews/tinacms-review/); [Wisp – Tina vs Decap](https://www.wisp.blog/compare/tina/decapcms)
- **Sanity** free tier: up to 3 users and 10,000 documents — [Wisp – Sanity vs Decap](https://www.wisp.blog/compare/sanity/decapcms); [We Build Stores – best CMS for Astro 2026](https://webuildstores.co.uk/insights/best-cms-for-astro/)
- **Google Sheets as CMS (example pipeline).** Edit the sheet, click Publish, a GitHub Action runs a sync script (pulls Drive photos, optimizes images, writes JSON), then Cloudflare builds and deploys the Astro site — [Akash Rajpurohit – "Your next backend could just be a Google Sheet"](https://akashrajpurohit.com/blog/your-next-backend-could-just-be-a-google-sheet/); [leabs/sheets-cms (Astro + Sheets)](https://github.com/leabs/sheets-cms); [Abhinav J – Astro + Google Sheets CMS](https://iabhinavj.com/blog/astro-google-sheets-cms/)
- **Scale.** Astro SSG with `getStaticPaths` suits small-to-medium datasets (< ~5,000 rows) — [pkglog Astro guide](https://pkglog.com/en/blog/astro-complete-guide/); [Solita – static site from JSON with Astro](https://dev.solita.fi/2024/12/02/building-static-websites-with-astro.html); [Astro content collections](https://docs.astro.build/en/guides/content-collections/)

### Inferences
- **Recommended path:**
  1. **Now:** product data in a JSON/CSV file in the repo (developer-maintained).
  2. **Next:** move to a **Google Sheet** with one row per product. Columns:
     - `kod`, `marka`, `kategori`, `alt_kategori`, `geometri`, `talas_kirici`, `kalite`, `malzeme_grubu` (P/M/K/N/S/H)
     - `ic`, `s`, `r`, `stok_durumu`, `aciklama`
     - `gorsel_url` (Drive), `muadiller`, `aktif` (E/H)

     The owner edits in the Google Sheets mobile app. A "Yayınla" step triggers a Cloudflare Pages deploy hook (via a bookmarked URL, an Apps Script menu, or a 1–2×/day scheduled GitHub Action) to rebuild.
     - Data validation dropdowns in Sheets reduce errors.
     - Turkish UI is native in Google Sheets.
  3. **Blog:** TinaCMS for visual editing on the phone (2 free users), or Decap if no external account is wanted. Both store Markdown in Git.
- Sanity or Airtable make sense only if the catalog grows into thousands of SKUs with relations (holders ↔ inserts ↔ spare parts) or multiple editors. Both add API quotas and an English UI.
- Always build to static HTML so the site stays portable (see §6 blocking risk). Never fetch the Sheet at runtime from the browser: that would expose the sheet and slow pages.

## 8. Analytics without cookie banners (Cloudflare Web Analytics, Plausible, Umami, GoatCounter) vs GA4

### Takeaway
**Cloudflare Web Analytics** (free, no cookies, no fingerprinting) is the default choice on Cloudflare Pages. Add **Umami Cloud Hobby** (free, 100K events, cookieless) if WhatsApp-click events are needed. **GA4 requires KVKK-compliant explicit consent and a banner.** GoatCounter's free tier is non-commercial only. Plausible has no free tier.

### Cited Findings
- **Cloudflare Web Analytics** is free, cookieless, does not fingerprint via IP/User-Agent, and does not track users across sites or over time. It lacks per-user journeys, custom events and funnels — [Cloudflare press release (2020)](https://www.businesswire.com/news/home/20200929005178/en/Cloudflare-Announces-Web-Analytics-a-Privacy-First-Free-Alternative-for-All-Website-Owners); [ConsentStack – Cloudflare WA GDPR](https://www.consentstack.io/vendors/cloudflare-web-analytics); [Humblytics](https://humblytics.com/blog/website-analytics-without-cookies-complete-guide-for-2025); [Tunde.io](https://www.tunde.io/posts/cloudflare-web-analytics)
- **Plausible.** No permanent free tier (30-day trial). Cloud from about **€6/month for 10k pageviews**. Cookieless — [Analytics-Alternatives – Plausible vs Umami](https://analytics-alternatives.com/compare/plausible-vs-umami/); [Hardal – cookieless platforms 2026](https://usehardal.com/blog/top-12-cookieless-analytics-platforms)
- **Umami.** Self-hosted is free (MIT). **Cloud Hobby $0 with 100K events**; Pro $20/month. Cookieless, using a daily salted hash — [Analytics-Alternatives](https://analytics-alternatives.com/compare/plausible-vs-umami/); [GoatCounter vs Umami](https://analytics-alternatives.com/compare/goatcounter-vs-umami/)
- **GoatCounter.** Hosted free tier is **non-commercial only**; commercial plans from about €5/month. Cookieless — [MakerStack – GoatCounter review 2026](https://makerstack.co/reviews/goatcounter-review/); [Analytics-Alternatives](https://analytics-alternatives.com/compare/goatcounter-vs-umami/)
- **GA4 / standard Google Analytics** are not "strictly necessary" under the KVKK cookie guide and require açık rıza. Running them without consent is unlawful — [Esenyel Partners](https://www.esenyelpartners.com/tr/kvkk-cerez-rehberi-uyarinca-web-siteleri-icin-uyum-yol-haritasi/); [Dijilegal](https://dijilegal.com/blog/cerez-politikasi-kvkk-rehberi)
- **Cloudflare and KVKK.** Cloudflare Web Analytics is presented as a reasonable KVKK-compatible option — [Cookienox 2026](https://cookienox.com/blog/cloudflare-turkiye-gizlilik/)

### Inferences
- **Stack recommendation:**
  - Cloudflare Web Analytics, enabled in the Pages project; it injects automatically when the domain is proxied. It gives page views, referrers, countries and Core Web Vitals.
  - Plus first-party redirect counting for WhatsApp clicks (`/wa?src=…` from §5), or Umami Cloud Hobby events (`umami.track('whatsapp_click', {urun:'CNMG120408'})`; API from background knowledge, verify).
  - Plus **Google Search Console**, which needs no tracking code on visitors, for queries, impressions and indexation. Search Console is the most important SEO tool here.
- Avoid GA4 unless a consent banner is acceptable. Mobile B2B visitors would see the banner on every first visit, and the KVKK guide requires equal Accept and Reject buttons.
- Even cookieless analytics processes IP addresses transiently and sends data to a foreign provider. Mention the tool in the Gizlilik Politikası and confirm the cross-border transfer basis with counsel ⚖️ (see §4).

### Gaps
- Not fetched: Cloudflare's current Web Analytics docs (any 2026 changes, e.g. automatic enablement or limits). A 2026 blog says Cloudflare adds analytics by default, but it was not verified — [Cittago](https://cittago.com/blog/cloudflare-web-analytics-automatica-2026/)
- Not confirmed: Umami Cloud's Hobby-tier commercial-use terms and data-region options (EU vs US).
